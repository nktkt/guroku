# Migrating from v1.1 to v1.2

## TL;DR
Drop in v1.2. Nothing in your `package.json`, `guroku.lock`, CLI scripts, or embedding code needs to change. The default resolver becomes pubgrub-based, but the public API and lockfile schema are unchanged.

## What changed under the hood
- New default resolver. `guroku install` now solves with pubgrub by default. The v1.1 BFS + single-step-backtracking path is still in the binary; set `GUROKU_RESOLVER=bfs` to force it.
- New module: `guroku::pubgrub_resolver::resolve_with_pubgrub`. Embedders that want pubgrub-grade resolution explicitly can call it directly.
- Existing v1.1 entry points (`resolver::resolve`, `resolver::resolve_with_overrides`, `resolver::resolve_with_manifest_overrides`) are unchanged. They remain the BFS path.

## What you might observe
- For projects that previously errored with `version conflict for X` from a cascade — those probably resolve now.
- For projects that previously resolved fine — same lockfile, byte-identical, against the same registry state.
- For projects with file: or git: roots — pubgrub falls back to BFS internally for those, so behaviour is identical to v1.1.

## What you don't need to do
- No `package.json` edits.
- No lockfile migration.
- No CLI script changes.
- No `Cargo.toml` change for embedders unless you want to pin a new minimum guroku version.

## What you might want to do
- Update CI to run with `GUROKU_RESOLVER=bfs` ALONGSIDE the default for one release cycle, to catch any unexpected lockfile drift.
- If you embed `guroku` and care about the new pubgrub path, consider switching imports from `resolver::resolve_with_manifest_overrides` to `pubgrub_resolver::resolve_with_pubgrub`.
- If you have a project that hits a pubgrub edge case, file an issue with the conflict report (the new `requested_by` payload) so we can patch it.

## Behaviour delta (full table)

| Surface | v1.1 | v1.2 |
|---------|------|------|
| `guroku install` default resolver | BFS + single-step backtrack | pubgrub |
| `guroku install` with `GUROKU_RESOLVER=bfs` | BFS + single-step backtrack | BFS + single-step backtrack |
| `resolver::resolve_with_manifest_overrides` | BFS + single-step backtrack | BFS + single-step backtrack |
| `pubgrub_resolver::resolve_with_pubgrub` | n/a | pubgrub |
| Lockfile schema | `lockfileVersion: 1` | `lockfileVersion: 1` |
| `guroku::prelude` | same | same |
| `Resolved.aliased_from` | populated for aliases | populated for aliases |
| `ResolutionConflict.requested_by` (BFS path) | `"a > b > c"` | `"a > b > c"` |
| `ResolutionConflict.requested_by` (pubgrub path) | n/a | pubgrub derivation report |

## Rollback
If v1.2 mis-resolves and you need v1.1 behaviour:
1. Set `GUROKU_RESOLVER=bfs` in the installing environment.
2. Or pin `guroku = "=1.1.x"` for embedders.

Both options keep working through v1.x — we don't plan to remove the BFS path before v2.0.

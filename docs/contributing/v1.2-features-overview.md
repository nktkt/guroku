# v1.2 features — a contributor's tour

## What landed
A real PubGrub-based resolver. v1.1's BFS + single-step backtracking handled diamonds with a single substitution; v1.2 handles cascading conflicts where one substitution forces another. The implementation pins `pubgrub = "0.2"` and uses it through a custom `DependencyProvider`.

## Module map (new + changed)
- `src/pubgrub_resolver.rs` — the new module. NpmVersion newtype, ResolutionPlan, NpmDependencyProvider, resolve_with_pubgrub.
- `src/commands/install.rs` — calls `pubgrub_resolver::resolve_with_pubgrub` by default. `GUROKU_RESOLVER=bfs` switches to the v1.1 path.
- `src/lib.rs` — `pub mod pubgrub_resolver;` added.
- `src/resolver.rs` — unchanged. The v1.1 BFS path remains the documented public API.
- `Cargo.toml` — `pubgrub = "0.2"` dep, version bumped to 1.2.0.

## Key types
- `NpmVersion` — wrapper around `node_semver::Version`. Implements `pubgrub::version::Version` (the trait pubgrub requires for Version types). `lowest()` returns 0.0.0; `bump()` increments patch and strips pre-release.
- `NpmDependencyProvider` — implements `pubgrub::solver::DependencyProvider<String, NpmVersion>`. Holds a prefetched `cache: HashMap<String, PackageMetadata>` and a `root_deps: BTreeMap<String, String>` for the synthetic root.
- `ResolutionPlan` — internal; describes the registry roots, local-name → registry-name mapping, and aliased_from map.
- `RootPlan::AllRegistry / HasLocal` — drives the file:/git: fallback decision.

## Two-phase flow
1. **plan_roots**: classify root specs, apply overrides, decompose aliases, decide whether to fall back to BFS.
2. **prefetch_closure**: BFS-prefetch every package name reachable in the dep graph from the registry roots. Each fetched at most once; uses the existing async `RegistryClient::fetch_metadata` with HTTP/ETag caching.
3. **pubgrub_resolve**: synchronous solve against the cache.
4. **materialise**: convert `SelectedDependencies` to `Resolution`, mapping registry names back to local names.

## Where to make changes
- **Add a new range conversion case** → `NpmDependencyProvider::npm_range_to_pubgrub`. The current implementation iterates candidates and unions singletons; if you find an edge case it doesn't handle, add a structural shortcut at the top of the function.
- **Improve conflict reports** → `translate_pubgrub_error`. Today we dump `DefaultStringReporter::report` into `requested_by`. A future contributor could parse the derivation tree and populate the structured `name`/`chosen`/`requested` fields too.
- **Support file:/git: roots in pubgrub** → currently we punt to BFS at `plan_roots` time. To support them, model "this version is the only candidate" and inject a singleton into the cache.
- **Drop pubgrub 0.2 → 0.3** → v1.3 backlog. The trait surface changed in 0.3; expect to rewrite `DependencyProvider` impl. Range conversion stays largely the same.

## Tests to add when changing the resolver
- Diamond conflict that v1.1 cannot solve but pubgrub can.
- Cascading conflict (3+ levels of backtracking).
- Conflict that has NO solution; assert the report mentions the relevant packages.
- Aliased root with a complex range that survives prefetch + solve + materialise.
- A root that points at file:/git: + a registry root, asserting the BFS fallback fires.

## How to debug a pubgrub failure
1. Set `GUROKU_LOG=trace` and re-run.
2. The `tracing::info!("resolving N root packages")` line tells you which path was taken.
3. If pubgrub fails, the `requested_by` field carries the `DefaultStringReporter` output. Read it bottom-up.
4. To compare against the v1.1 path, re-run with `GUROKU_RESOLVER=bfs` and inspect what THAT path picks.
5. To bypass the network entirely while debugging, write a fixture under `tests/fixtures/` that hand-crafts the metadata.

## Don't break
- The v1.0 stability surface (`guroku::prelude`, lockfile, CLI). Run `cargo test --test api_stability_*` and `cargo test --test cli_help_v1.rs` after every change.
- The v1.1 BFS path. Run `cargo test --test resolver_no_backtrack`, `tests/overrides_*`, `tests/specs_*`. They MUST still pass against `resolver::resolve_with_manifest_overrides`.
